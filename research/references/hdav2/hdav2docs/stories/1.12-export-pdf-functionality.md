## User Story

**As a** user who has completed document translations,
**I want to** export my translated documents as PDFs with OS save dialog for choosing save location,
**So that** I can save translated PDFs exactly where I want with proper multi-script rendering.

## Context

- ✅ PDF upload and text extraction
- ✅ E2E multi-language translation workflow (10 languages: hi, mr, bn, gu, de, en, ta, te, kn, ml)
- ✅ Auto-translate pipeline with Vertex AI Gemini 2.0 Flash Thinking Experimental

**Session 5-6 Implementation Issues**:

**Decision**: Complete rewrite with **frontend-only approach** for simplicity and better UX control.

### Frontend PDF Generation Requirements

**Library Choice**: **pdfmake** (recommended) or jsPDF
- **Why pdfmake**: Better support for complex layouts, built-in multi-script font support, declarative API
- **Why NOT jsPDF**: More manual control needed for page breaks and font handling

**Font Integration**:
- Load Base64 fonts from `Font/` directory:
  ```typescript
  import { notoSansDevanagariBase64 } from '@/fonts/notoSansDevanagariBase64';
  import { notoSansBengaliBase64 } from '@/fonts/notoSansBengaliBase64';
  import { notoSansGujaratiBase64 } from '@/fonts/notoSansGujaratiBase64';
  ```
- Register fonts with pdfmake:
  ```typescript
  pdfMake.fonts = {
    Devanagari: {
      normal: notoSansDevanagariBase64,
      bold: notoSansDevanagariBase64,
      // ... (pdfmake uses base64 directly)
    },
    Bengali: { normal: notoSansBengaliBase64 },
    Gujarati: { normal: notoSansGujaratiBase64 },
    // Roboto for English/German (default in pdfmake)
  };
  ```

**Page Structure Preservation** (CRITICAL):
1. **Parse page markers**: Split text by `# [Page N]` regex
2. **One page marker → One PDF page**:
   - Page 1 content (from `# [Page 1]` to `# [Page 2]`) → PDF Page 1
   - Page 2 content (from `# [Page 2]` to `# [Page 3]`) → PDF Page 2
3. **A4 page size**: 595.28 x 841.89 points (standard A4)
4. **Font size reduction logic**:
   ```typescript
   // Start with base font size (e.g., 12pt)
   let fontSize = 12;

   // Calculate text height for current page content
   while (textHeight > pageHeight && fontSize > 6) {
     fontSize -= 0.5; // Reduce font size in 0.5pt increments
     recalculateTextHeight();
   }

   // If still doesn't fit at 6pt, show warning (edge case)
   ```
5. **Margins**: Standard margins (40pt top/bottom, 40pt left/right)

**OS Save Dialog Trigger**:
- **Method 1 (pdfmake)**: Use `download()` method with proper filename
  ```typescript
  pdfMake.createPdf(docDefinition).download(filename);
  // This triggers browser save dialog automatically
  ```
- **Method 2 (Manual blob)**: Create blob and use `<a>` tag
  ```typescript
  pdfMake.createPdf(docDefinition).getBlob((blob) => {
    const url = URL.createObjectURL(blob);
    const link = document.createElement('a');
    link.href = url;
    link.download = filename; // Triggers save dialog
    link.click();
    URL.revokeObjectURL(url);
  });
  ```

**ZIP Generation** (for multi-language):
- Use **JSZip** library (already common in frontend projects)
- Create PDFs in memory, add to ZIP, trigger download:
  ```typescript
  const zip = new JSZip();

  for (const lang of selectedLanguages) {
    const pdfBlob = await generatePDF(documentText[lang], lang);
    zip.file(`${originalFilename}_translated_${langName}.pdf`, pdfBlob);
  }

  const zipBlob = await zip.generateAsync({ type: 'blob' });
  const link = document.createElement('a');
  link.href = URL.createObjectURL(zipBlob);
  link.download = `${originalFilename}_${langCodes.join('_')}.zip`;
  link.click();
  ```

### File Naming Convention

**Single Language Export**:
- Format: `{original_filename}_translated_{language_name}.pdf`
- Examples:
  - Original: "The Beggar Princess.pdf" + Hindi → `The Beggar Princess_translated_hindi.pdf`
  - Original: "Book.pdf" + Marathi → `Book_translated_marathi.pdf`
- User can edit filename in OS save dialog

**Multi-Language ZIP Export**:
- Format: `{original_filename}_{lang_code1}_{lang_code2}_{lang_code3}.zip`
- Examples:
  - Original: "Book.pdf" + Hindi + Marathi → `Book_hi_mr.zip`
  - Original: "Guide.pdf" + Hindi + Marathi + Bengali → `Guide_hi_mr_bn.zip`
- Contents of ZIP:
  - `Book_translated_hindi.pdf`
  - `Book_translated_marathi.pdf`
  - `Book_translated_bengali.pdf`

## Technical Implementation

### Architecture Overview (Frontend-Only)
```
┌──────────────────────┐
│  Complete Stage      │
│  EditorToolbar.tsx   │
│  "Export Document"   │
└──────────┬───────────┘
           │ onClick
           ▼
┌────────────────────────────────────┐
│  ExportPDFModal.tsx                │
│  - Language checkboxes             │
│  - Page selection (radio)          │
│  - Format selection (PDF only)     │
│  - Export summary                  │
└──────────┬─────────────────────────┘
           │ onExport()
           ▼
┌────────────────────────────────────┐
│  export-store.ts                   │
│  - Fetch document data from store  │
│  - Fetch translation text          │
│  - Generate PDF(s) in browser      │
└──────────┬─────────────────────────┘
           │
           ▼
┌────────────────────────────────────┐
│  PDF Generation (pdfmake)          │
│  - Parse page markers              │
│  - Create page-by-page layout      │
│  - Register Base64 fonts           │
│  - Calculate font sizes            │
│  - Generate PDF blob               │
└──────────┬─────────────────────────┘
           │
           ▼
┌────────────────────────────────────┐
│  Download Handler                  │
│  - Single PDF → pdfMake.download() │
│  - Multiple PDFs → JSZip → blob    │
│  - Trigger OS save dialog          │
└────────────────────────────────────┘
```

### Data Flow
1. **User Action**: Click "Export Document" in Complete stage toolbar
2. **Modal Open**: Fetch available languages from editor store (already loaded)
3. **User Selection**: Choose languages + page range (All/Current/Range) + format (PDF)
4. **Export Trigger**: Click "Export" button
5. **Data Fetching**: Get translation text from editor store or API
6. **PDF Generation** (client-side):
   - Parse page markers: `# [Page 1]`, `# [Page 2]`, etc.
   - For each selected language:
     - Create pdfmake document definition
     - Map language to appropriate font (Devanagari/Bengali/Gujarati/Roboto)
     - Build content array with page breaks
     - Calculate font sizes per page (reduce if needed)
     - Generate PDF blob
7. **ZIP Creation** (if >1 language):
   - Add all PDF blobs to JSZip
   - Generate ZIP blob
8. **Download**: Trigger OS save dialog with proper filename

## Notes

### Why Frontend-Only Approach?
1. **Simpler architecture**: No workers, no queues, no polling
2. **Better UX control**: Direct access to browser download API (OS save dialog)
3. **Fewer failure points**: No network calls, no backend dependencies
4. **Faster development**: Pure TypeScript, no Python/backend changes
5. **User expectation**: Modern web apps do client-side PDF generation (invoices, receipts, etc.)

### Limitations of Frontend Approach
- **Browser memory**: Large documents (500+ pages) may cause browser slowdown
- **Font file size**: Base64 fonts increase bundle size (~1.7MB for 3 fonts)
- **Processing time**: Client CPU-bound (slower for old devices)

### Mitigations
- **Code splitting**: Lazy load pdfmake and fonts only when export modal opens
- **Progress indicators**: Show clear feedback during generation
- **Memory optimization**: Stream PDFs if possible, release blobs after download
- **Font subsetting**: Consider using font subsets (only glyphs needed for document)

### Alternative Considered: Hybrid Approach
- Backend generates PDF, frontend triggers OS save dialog via blob
- **Rejected**: Still requires backend complexity, loses simplicity advantage
