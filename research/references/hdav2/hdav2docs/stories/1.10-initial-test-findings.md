## Critical Issues Found

### 🔴 Issue #1: Foreign Key Ambiguity (BLOCKER)

**Error**: `PGRST201` - PostgREST cannot determine which relationship to use

**Console Output**:
```
Error fetching tasks: {
  code: PGRST201,
  message: "Could not embed because more than one relationship was found for 'translation_results' and 'documents'",
  hint: "Try changing 'documents' to one of the following: ... Find the desired relationship in the 'details' key."
}
```

**Root Cause**:
The `translation_results` table likely has **multiple foreign keys** pointing to `documents`:
1. `document_id` → `documents(id)` (primary relationship)
2. Possibly another column (e.g., `source_document_id`, `parent_document_id`) → `documents(id)`

**Impact**:
- Translation jobs cannot be fetched from database
- Frontend shows 0 translation jobs even if data exists
- Queue page completely broken for translation pipeline

**Fix Required**:
```sql
-- Check current foreign keys
SELECT
    tc.constraint_name,
    kcu.column_name,
    ccu.table_name AS foreign_table_name,
    ccu.column_name AS foreign_column_name
FROM information_schema.table_constraints AS tc
JOIN information_schema.key_column_usage AS kcu
    ON tc.constraint_name = kcu.constraint_name
JOIN information_schema.constraint_column_usage AS ccu
    ON ccu.constraint_name = tc.constraint_name
WHERE tc.constraint_type = 'FOREIGN KEY'
    AND tc.table_name = 'translation_results'
    AND ccu.table_name = 'documents';

-- Solution: Use explicit foreign key naming in Supabase query
-- In queue-store.ts line ~403:
.from('translation_results')
.select(`
  *,
  documents!translation_results_document_id_fkey(*)  // Explicit FK name
`)
```

**Story 1.10 Update**: Add database investigation step + frontend query fix

### 🔴 Issue #2: Extraction Jobs Not Displaying (CRITICAL)

**Observation**:
- Console logs show: `Extraction jobs query result: {data: Array(7), error: null}`
- Database has **7 completed extraction jobs**
- UI shows: **0** jobs in all columns (Queued, Processing, In Review, Completed)

**Root Cause Analysis**:
Frontend successfully fetches 7 extraction jobs but fails to transform/display them.

**Possible Causes**:
1. ❌ **Status Mismatch**: Jobs have `status='completed'` but UI expects `status='in-review'`
2. ❌ **Missing Pipeline Field**: Jobs missing `pipeline='extraction'` field
3. ❌ **Data Transformation Bug**: Store fails to map database rows to UI `DocumentTask` type
4. ❌ **Filter Bug**: All jobs filtered out by status/owner/priority logic

**Frontend Code Location**: `frontend/src/store/queue-store.ts:241`

**Fix Required**:
1. Check database: What status do the 7 jobs actually have?
   ```sql
   SELECT id, document_id, status, created_at
   FROM text_extraction_results
   ORDER BY created_at DESC;
   ```

2. Update store transformation logic to handle old status values:
   ```typescript
   // In queue-store.ts - normalize old status values
   const normalizeStatus = (status: string): ProcessingStatus => {
     const statusMap: Record<string, ProcessingStatus> = {
       'text-processing': 'processing',
       'queued_manual': 'queued',
       'completed': 'completed',  // Should these be 'in-review'?
       // ... etc
     };
     return statusMap[status] || status as ProcessingStatus;
   };
   ```

3. Ensure `pipeline: 'extraction'` is set for all extraction jobs

**Story 1.10 Update**: Add data transformation fix + status normalization
