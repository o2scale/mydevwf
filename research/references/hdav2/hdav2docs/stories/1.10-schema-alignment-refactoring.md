- Missing review workflow columns
- Status values not yet migrated in code

- ❌ Workers will fail to update job status (column mismatch)

## Schema Changes from Story 1.9 (Reference)

### 1. `text_extraction_results` - New Columns Added
```sql
- review_status VARCHAR(50) DEFAULT 'pending'
- reviewer_id UUID (FK to auth.users)
- reviewed_at TIMESTAMP WITH TIME ZONE
- review_notes TEXT
- started_at TIMESTAMP WITH TIME ZONE
- processing_duration_ms INTEGER
```

### 2. `translations` → `translation_results` - Renamed + Restructured
```sql
- Table renamed from "translations" to "translation_results"
- 41 total columns including:
  - target_language TEXT (one row per language)
  - priority INTEGER (1-10)
  - process_immediately BOOLEAN
  - translated_text TEXT
  - character_count INTEGER
  - word_count INTEGER
  - review_status VARCHAR(50)
  - reviewer_id UUID
  - reviewed_at TIMESTAMP
  - review_notes TEXT
  - queued_at TIMESTAMP
  - started_at TIMESTAMP
  - completed_at TIMESTAMP
  - processing_duration_ms INTEGER
  - tenant_id UUID
```

### 3. `documents` - Pipeline Tracking Added
```sql
- current_pipeline VARCHAR(50) DEFAULT 'extraction'
- extraction_status VARCHAR(50)
- translation_status VARCHAR(50)
- extraction_job_id UUID
- translation_job_id UUID
```

### 4. Unified Status Values
```
Old: 'text-processing', 'queued_manual'
New: 'queued', 'processing', 'in-review', 'completed', 'failed'
```
