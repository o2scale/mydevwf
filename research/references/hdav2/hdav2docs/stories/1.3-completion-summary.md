### Background Worker

#### Text Extraction Worker
**File**: `backend/workers/text_extraction_worker.py`

**Features**:
- Polls pgmq `text_extraction_queue` every 2 seconds
- Downloads PDF from Supabase Storage
- Processes document in batches (10 pages per batch)
- Sends PDF chunks directly to Vertex AI (no image conversion)
- Inserts page markers in exact format: `# [Page N]`
- Updates job progress in real-time
- Handles errors with job failure states

**Key Functions**:

1. **`run()`** - Main worker loop
   - Polls pgmq queue
   - Processes jobs sequentially
   - Archives completed messages

2. **`process_extraction_job(job_data)`** - Job processing logic
   - Updates status to "processing"
   - Downloads PDF from Supabase Storage
   - Creates page batches (10 pages each)
   - Processes each batch sequentially
   - Combines results with page markers
   - Updates job as "completed" or "failed"

3. **`extract_text_from_pdf_chunk(chunk_pdf_bytes, start_page, end_page)`** - Vertex AI integration
   - Sends PDF chunk to Gemini 2.5 Pro
   - Uses `application/pdf` mime type
   - Returns extracted text

**Processing Flow**:
```
1. Poll pgmq queue → 2. Download PDF → 3. Create batches (10 pages each)
↓
4. For each batch:
   - Extract pages 1-10 as new PDF
   - Send to Vertex AI
   - Get extracted text
   - Update progress (33%, 67%, 100%)
↓
5. Combine results → 6. Insert page markers → 7. Save to database
```

```python
def extract_text_from_pdf_chunk(self, pdf_bytes: bytes, start_page: int, end_page: int):
    """
    Extract text from PDF chunk using Vertex AI

    Args:
        pdf_bytes: PDF file bytes (10 pages)
        start_page: Starting page number
        end_page: Ending page number

    Returns:
        (extracted_text, token_count)
    """
    prompt = """Extract all text from this PDF document.

Requirements:
- Preserve original text layout and structure
- Maintain paragraph breaks and formatting
- Include all text content
- Output plain text only, no additional commentary

Extract the text:"""

    # Send PDF directly to Vertex AI
    parts = [
        Part.from_text(prompt),
        Part.from_data(data=pdf_bytes, mime_type="application/pdf")
    ]

    response = self.model.generate_content(parts)

    # Insert page markers
    text_with_markers = self.insert_page_markers(response.text, start_page, end_page)

    return text_with_markers, response.usage_metadata.candidates_token_count
```

**Key Benefits**:
- No image conversion required (removed pdf2image dependency)
- No poppler system dependency
- Better OCR accuracy with native PDF
- Smaller data transfer (PDF < Images)
- Faster processing (no conversion overhead)

### PDF Utilities

#### PDF Page Extraction
**File**: `backend/api/utils/pdf_utils.py`

**Functions**:

1. **`extract_pdf_pages(pdf_bytes, start_page, end_page)`**
   - Extracts specific pages from PDF
   - Returns new PDF bytes containing only those pages
   - Example: Extract pages 11-20 from 500-page PDF

2. **`create_page_batches(total_pages, pages_per_batch=10)`**
   - Creates batch ranges for processing
   - Example: 27 pages → [(1,10), (11,20), (21,27)]

**Implementation**:
```python
def extract_pdf_pages(pdf_bytes: bytes, start_page: int, end_page: int) -> bytes:
    """Extract pages from PDF and return as new PDF"""
    pdf_reader = PdfReader(io.BytesIO(pdf_bytes))
    pdf_writer = PdfWriter()

    # Add pages (0-indexed)
    for page_num in range(start_page - 1, end_page):
        if page_num < len(pdf_reader.pages):
            pdf_writer.add_page(pdf_reader.pages[page_num])

    # Write to bytes
    output_buffer = io.BytesIO()
    pdf_writer.write(output_buffer)
    return output_buffer.getvalue()

def create_page_batches(total_pages: int, pages_per_batch: int = 10) -> List[tuple]:
    """Create batch ranges"""
    batches = []
    for start in range(1, total_pages + 1, pages_per_batch):
        end = min(start + pages_per_batch - 1, total_pages)
        batches.append((start, end))
    return batches
```

## Major Technical Decisions

### Decision 1: PDF-Direct Approach (vs Image-Based)
**Changed During Development**

**Original Plan**: Convert PDF to images, send images to Vertex AI
**Final Implementation**: Send PDF chunks directly to Vertex AI

**Reason for Change**: User feedback - "PDF direct gives better results always"

**Benefits**:
- ✅ No poppler system dependency
- ✅ Better OCR accuracy
- ✅ Smaller data transfer (PDF < Images)
- ✅ Faster processing (no conversion)
- ✅ Simpler deployment (no system dependencies)

**Trade-offs**:
- None - this was a pure improvement

---

### Decision 2: Fixed 10 Pages per Batch (vs Token-Based)
**Changed During Development**

**Original Plan**: Dynamic batching based on token estimation
**Final Implementation**: Fixed 10 pages per batch

**Reason**:
- Vertex AI output limit: 65K tokens
- Conservative estimate: 10 pages × 6,500 tokens = 65K (safe)
- Prevents output truncation on dense pages

**Examples**:
- 500 pages → 50 batches (49×10 + 1×10)
- 498 pages → 50 batches (49×10 + 1×8)
- 27 pages → 3 batches (10+10+7)

**Token Estimation**: ~650 tokens per page (conservative)

---

### Decision 3: Page Marker Format
**CRITICAL - Frontend Dependency**

**Format**: `# [Page N]` (exact spacing, capitalization)

**Frontend Regex**: `/^#\s*\[Page\s+(\d+)\]$/i`

**Examples**:
```
# [Page 1]
MIRACLES
DO STILL HAPPEN

# [Page 2]
Third Edition:
2012
```

**Why Critical**:
- Frontend editor depends on this exact format
- If wrong: editor breaks, page navigation fails, total page count shows 0
- Validated with 27-page test: 27/27 markers found ✅

## Error Handling

### Implemented Error Cases

1. **Document Not Found**
   - HTTP 404: "Document not found"
   - Validates document exists before creating job

2. **Invalid Document Status**
   - HTTP 400: "Document status must be 'uploaded' or 'completed'"
   - Prevents processing documents that are already processing or failed

3. **Vertex AI API Failure**
   - Job status: "failed"
   - Error message saved to database
   - Document status: "failed"

4. **PDF Download Failure**
   - Job status: "failed"
   - Error message: "Failed to download PDF from storage"

5. **Worker Crash**
   - pgmq message stays in queue (5-minute visibility timeout)
   - Worker picks up message again after restart
   - Prevents job loss
