## Overview

Story 1.5 implemented a parallel worker architecture to enable concurrent text extraction job processing, improving throughput from 1 job at a time to 4 simultaneous jobs.

## Architecture Decision

### Initial Approach: Multiprocessing (Deprecated)
- Attempted using Python `multiprocessing.Process` to spawn 4 worker processes
- **Issue**: Python 3.13 on Windows uses `spawn` method which requires pickling
- **Error**: `TypeError: cannot pickle 'weakref.ReferenceType' object`
- Signal handlers created weakref objects that couldn't be pickled
- **Conclusion**: Abandoned in favor of async approach

### Final Approach: Single-Process Async Pool ✅
- Single process with 4 concurrent async coroutines using `asyncio`
- Each worker polls the pgmq queue independently
- Shared database connection for queue polling
- Individual Supabase clients and Vertex AI services per worker
- **Benefits**:
  - No pickle issues
  - Simpler than multiprocessing
  - Less overhead
  - Easier debugging
  - Works perfectly on Windows
  - True concurrent processing via async/await

## Lessons Learned

### 1. Python Multiprocessing on Windows
- Windows uses `spawn` method (not `fork`)
- Requires pickling all objects
- Signal handlers cause pickle issues
- Async approach is simpler and equally effective

### 2. Process Management
- Important to track and clean up background processes
- Single async process is easier to manage than multiple processes
- Fewer resources, less complexity

### 3. Queue Polling Strategy
- Independent polling per worker works well
- 2-second polling interval balances responsiveness and overhead
- Visibility timeout prevents duplicate processing

1. Run worker pool as a systemd service (Linux) or Windows Service
2. Set `WORKER_POOL_SIZE` based on CPU cores and API rate limits
3. Monitor worker status endpoint for health checks
4. Set up alerts for failed jobs
5. Configure automatic restart on failure

### Resource Requirements
- **Memory**: ~250MB per worker pool process
- **CPU**: Shared across 4 async workers
- **Network**: Outbound to Google Vertex AI API
- **Database**: 1 connection per worker pool process
